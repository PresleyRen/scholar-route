# 研究探索方案：版本感知记忆与故障恢复

## 1. 当前判断

**最值得先做的是可追踪的可靠性实验，先检验简单规则是否已经足够。** 目前无法证明存在新的 Agent 记忆方法，也无法证明错误分类是减少重复执行的必要机制。唯一输入是开发者在虚构规划 brief 中描述的两项未计数观察：长对话后的摘要可能丢失版本信息；工具超时后的重试可能重复执行。[本地输入：evidence/agent-brief.md，Working observation；LOCAL-BRIEF-01/L2]

现有系统仅被描述为小型 Python 控制器、检索、摘要记忆、两个工具和一个重试循环；本轮没有控制器源码、日志、真实数据集、模型配置或基准结果。这里的架构建议是待核对的接口设计，不是对原代码的审计结论。[LOCAL-BRIEF-01/L1]

推荐把问题拆成“记忆何时失效”和“失败后是否应重做”两条可独立否证的研究线。第一条先确认来源版本与依赖追踪能否超越完整版本清单缓存；第二条先确认错误分类能否在相同幂等与状态核查基础上增加价值。若收益分别全部被缓存和幂等规则解释，采用这些简单方案并如实报告，不把组合包装成原创算法。

- **核心子域**：Agent memory/context；retrieval and evidence grounding；versioned cache/dependency invalidation；idempotent execution/retry/recovery；biomedical article correction/version provenance。
- **后续时间窗**：Agent 直接竞品先覆盖 2022-01-01 至实际检索日；缓存、事务、重试与来源追踪经典方法不设起年，通过主题词与引用链补齐。此选择是计划边界，非学科起源断言。
- **语言和类型**：英文与中文；正式期刊、会议、预印本、官方代码/数据与规范资料分开记录。会议文献保留在相关工作中，未来期刊投稿池只纳入期刊。
- **材料来源**：拟用 DBLP/OpenAlex/Crossref/arXiv 与原始出版页；PubMed/PMC/Europe PMC；中文数据库合法可访问记录或用户导出。实际本轮只读本地 brief。
- **排除范围**：纯临床疗效、患者个体诊断、药物/化学“agent”、没有语言模型的经济主体；纯营销材料不作为效果证据。邻近系统方法只要可解释候选机制，仍纳入。
- **停止条件**：完成协议内各概念组初检和关键竞品引用追踪，保留访问/页数/命中边界；不声称穷尽全领域。未检索的空白单元仍为“待检索”。

## 5. 竞争解释与识别办法

| 竞争解释 | 为什么会混淆 | 最小区分证据 | 导致收缩或否定的情况 |
|---|---|---|---|
| 简单缓存已足够 | 版本标签和整体失效可能解决全部旧答案 | 带所有依赖文档版本清单的规则缓存 | 新方案成功率相当且没有明确资源收益 |
| 多读资料或多花模型预算 | 新方法可能只是拿到更多新文本 | 同一语料快照、版本目录、检索上限、输入/输出预算；完整记账 | 等预算后差异消失 |
| 摘要失真不在版本层 | 数值、条件、否定句或来源内容被删掉也会错 | 分别注入只丢版本、只丢内容、二者均保留；人工核对原文片段 | 版本齐全仍同样出错，需改研究对象 |
| 检索失败或模型不遵循证据 | 记忆正确并不意味着检索/答案正确 | oracle evidence 条件、证据选中率、答案引用校验 | 错误主要来自检索/生成，不能归因记忆 |
| 幂等规则已消除重复效果 | 超时不能确定动作是否已提交 | 同幂等键/状态核查的规则重试 | 类型策略只优于无幂等的弱基线 |
| 错误分类泄漏故障真值 | 注入器知道“提交后丢响应”，控制器不应知道 | 故障真值只进评分器，策略只读真实可观测错误与日志 | 使用隐藏标签才改善，部署主张无效 |
| 有利任务/评测泄漏 | 对同一文章改问法不构成独立样本 | 按文章家族分开发/测试，固定生成种子与病例清单 | 测试后调参则降格开发证据 |
| 过度拒答造成低错误率 | 总拒绝也会得到零旧答案和零重复 | 联合记录有效完成率、错误、拒答与开销 | 错误降低但任务完成率明显损失 |

这些是本项目的待检验解释，不是文献已确认的原因。FIELD_EVIDENCE_MAP.md 将每个关键主张与证据缺口连到实验。

## 6. 两个问题与优先顺序

**RQ1：在相同模型、版本目录、语料、检索与上下文预算下，来源依赖的选择性失效，能否比完整版本清单的规则缓存提高正确且版本可追溯的问答完成率？**

首要比较 D 对 C；摘要记忆 A 用于复现起点，始终新检索 B 用于检验是否根本需要持久记忆。零变化条件检测过度失效；历史 as-of 问题检测错误地把“新版本”一律当成正确答案。主要问题不把同等准确率下的成本节省偷换成能力提升。

**RQ2：在相同幂等键、超时后状态核查与尝试预算下，按可观测错误类别选择恢复动作，能否减少无效重试而保持有效完成率？**

首要比较类型策略 R2 对规则恢复 R1。R0 显示原始通用重试的风险；移除幂等的 R3 只解释机制。若重复执行的下降全部来自幂等，结论应归于幂等而非错误分类。

先做 RQ2 的零模型故障轨迹与记账接口，因为它也为 RQ1 提供可信的计数和中断恢复。然后做 RQ1 的离线受控状态案例；工具和评分器通过后，再开展有上限的模型试点。EXPERIMENT_PROTOCOL.md 给出全部分组、分母和停止规则。

| 方向 | 可行性判断 | 新颖性风险 | 评价可信度的前提 | 适合的下一步 |
|---|---|---|---|---|

| 生物医学应用贡献 | 当前只有文献任务背景 | 尚无法评估 | 真正文章来源/许可/版本与专家可核对的语义 | 先保持文献忠实性范围，暂不扩展临床主张 |
