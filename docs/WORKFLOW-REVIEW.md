# 工作流冲突场景审查

日期：2026-10-20。执行方式：本次助手读取现有技能正文后，对下列固定合成情境逐项应用整合规则，并保存处理产物。这里是工作流场景审查，不是独立模型盲测；不计入 118 项 Python 回归。18 条含原生行为的冲突另见 [覆盖索引](COVERAGE.md)。

每个场景比较容易冲突的两种处理方式，保留对当前任务有效的部分。以下内容均为合成情境，不对应真实论文、作者或期刊评价。

<a id="cf02"></a>
## CF02 · 质量判断、期刊适配、投稿顺序

**输入：** 只有 Agent 记忆研究摘要。一种流程按摘要给出“Q1 就绪、保底录用”；另一种流程拒绝安排投稿顺序。

**本次产物：** “先建立论文画像：机制是版本感知记忆，当前证据为摘要陈述。候选按机制相关性、文章类型、可比先例和预算排序；把缺少跨任务评测、预算匹配和消融列为补实验任务。可以形成主投/备选顺序，顺序依据是适配与执行条件。”

**取舍：** 保留前者的投稿规划、后者的科学批评分工；去掉由摘要自动推断个人录用机会的步骤。

**检查结果：** 给出了下一步行动和排序依据；没有把投稿策略改写成科学结论。涉及 `peer-review`、`fit-comparison`、`submission-plan`。

<a id="cf11"></a>
## CF11 · 大刊命中数量与专刊机制适配

**输入：** 合成候选 A 有 100 篇宽泛 AI 论文；B 有 3 篇使用同类故障模型、同预算比较的 Agent 恢复论文。

**本次产物：** “分别抽取两刊实际论文的贡献类型、工作负载和评测要求。当前输入支持 B 的机制相似度更强，A 的数量用于补充召回。优先调查 B 的范围与文种，保留 A 作为宽领域候选。”

**取舍：** 保留数量检索的召回作用，用实际可比论文决定适配。

**检查结果：** 没有把 100:3 当成适配比例；B 的优先级附带可追溯的比较理由。涉及 `fit-comparison`。

<a id="cf14"></a>
## CF14 · 目录缺失与出版风险

**输入：** 一份社区表将“不在 DOAJ”直接标为风险；合成期刊采用订阅模式，官网与 ISSN 对应且收费政策清楚。

**本次产物：** “记录为订阅路径；DOAJ 检索结果保留为目录信息。风险调查继续核对身份、同行评审说明、费用和联系方式，当前输入中没有据此判定不当出版的证据。”

**取舍：** 保留风险排查，改用与出版模式相符的证据。

**检查结果：** 未把目录缺失、低价格或订阅模式当作不当行为。涉及 `journal-integrity`。

<a id="cf15"></a>
## CF15 · 中文目录与商业中介

**输入：** 用户要求中文核心、低费用；检索来的技能要求一律通过指定付费平台提交。

**本次产物：** “按用户指定目录、学科、文种与费用形成候选；核对官方投稿入口。商业平台仅作为候选线索来源，不改变排序或新增必缴费用。”

**取舍：** 保留中文目录路线，去掉强制平台和推广优先级。

**检查结果：** 投稿路径回到期刊官方说明，保留用户原预算。涉及 `regional-indexing`。

<a id="cf21"></a>
## CF21 · 润色与论证核查

**输入：** 原文：`Success increased from 48.0% to 51.2% on one synthetic workload.` 润色提议改为 `Our method proves superior and achieves 61.2% across real-world tasks.`

**本次产物：** `On the synthetic workload, the method increased success from 48.0% to 51.2%. The experiment measures performance under this workload and motivates tests on additional tasks.`

**取舍：** 保留清晰直接的改写；数值、任务范围、证据强度由同一论证核查记录约束。核查角色提出建议，由改写负责人统一落稿。

**检查结果：** 48.0%、51.2%、单个合成负载保持一致；没有引入真实任务结果。涉及 `argument-audit`、`manuscript-writing`。

<a id="cf22"></a>
## CF22 · 署名与 CRediT 声明

**输入：** 只知道甲写代码、乙收集数据。模板要求填写所有作者“同意最终稿、无利益冲突、共同设计”。

**本次产物：** “甲：Software；乙：Data curation。设计贡献、最终稿确认和利益冲突分别列为待作者填写字段，集中到同一声明记录。”

**取舍：** 保留模板的结构化收集价值，用实际贡献填写具体项。

**检查结果：** 没有从沉默推断同意或贡献。涉及 `authorship-credit`。

<a id="cf23"></a>
## CF23 · 多视角审稿与多数投票

**输入：** 两个模拟审稿角色认可结果；第三个指出测试集被用于调参。流程 A 用多数意见通过，流程 B 检查具体证据。

**本次产物：** “将‘测试集参与调参’列为首要异议。核对数据拆分与实验日志；有泄漏时重新划分调参与测试数据并重跑。两个支持意见保留在贡献与表达评价中。”

**取舍：** 保留多视角互补，按问题证据与影响程度归并意见。

**检查结果：** 关键效度问题没有被投票抵消。涉及 `peer-review`。

<a id="cf24"></a>
## CF24 · 投稿准备与发送

**输入：** 用户让技能“准备投稿前询问信”，没有发送指令。

**本次产物：** “交付带真实贡献、拟投文章类型、期刊适配理由和明确询问事项的邮件草稿；发送状态保持 drafted。”

**取舍：** 保留完整可用的投稿准备，不把写草稿转换成发送。

**检查结果：** 输出可直接审阅；没有创建已发送或已投稿记录。涉及 `submission-preflight`、`cover-letter`。

<a id="cf25"></a>
## CF25 · 重复审批与多个项目根目录

**输入：** 已有研究目录和明确预算；某子流程要求重新建隐藏目录、再逐步重复询问相同偏好。

**本次产物：** “在原项目记录当前阶段、预算与已知决策；从已有文献和待办续做。只有新增实质性决策才提问，独立可做的检索与核查继续执行。”

**取舍：** 保留阶段记录，统一项目根目录与决策来源。

**检查结果：** 没有丢失原研究状态，也没有额外导出或上传项目材料。涉及 `state-map`、`intake`。

<a id="cf27"></a>
## CF27 · 领域能力与实际工具调用

**输入：** 生医 Agent 课题需要 PubMed；当前原生工具只有 OpenAlex、Crossref、DBLP 和 arXiv。

**本次产物：** “计划中保留 PubMed 专项检索；有宿主 PubMed 工具则调用并记录结果，否则登记为待执行查询。同时使用当前可用来源完成公共元数据检索，统一导入项目。”

**取舍：** 保留生医来源覆盖，通过实际可用的宿主接口补足原生接口。

**检查结果：** 四个原生适配器与其他宿主来源分工明确。涉及 `paper-search`、`implementation`。

<a id="cf28"></a>
## CF28 · 来源能力与文件再分发

**输入：** 一个公开仓库没有许可证；另一个仓库代码和数据采用不同许可证。用户要融合能力。

**本次产物：** “记录源仓库、完整提交、文件和能力特点；独立编写流程与测试。需要引入具体文件时，按该文件许可证检查并保留署名。”

**取舍：** 保留可追溯能力设计，将文档、代码、模板和数据库的引入分别处理。

**检查结果：** 当前项目只使用原创实现及来源映射。涉及 `state-map` 和来源清单维护。

<a id="cf29"></a>
## CF29 · 投稿格式与科学证据

**输入：** 稿件所有篇幅和附件检查通过，但实验只与弱基线比较。

**本次产物：** “投稿预检记录格式项通过；科学审查单独要求强单 Agent、同 token/调用预算和消融。将补充对照列入实验计划，再更新稿件论证。”

**取舍：** 保留快速格式检查，与科学论证检查并行。

**检查结果：** 格式通过没有覆盖实验缺口。涉及 `submission-preflight`、`peer-review`。

<a id="cf31"></a>
## CF31 · 已发表样本与当前投稿要求

**输入：** 去年发表文章采用双栏；本次目标文章类型的当前作者指南要求单栏审稿稿。

**本次产物：** “按当前指南生成单栏审稿文件；已发表样本用于学习图表密度、语气和读者预期。记录指南获取日期及文章类型。”

**取舍：** 保留样本的风格参考作用，由当前阶段要求决定文件格式。

**检查结果：** 输出格式与本次投稿阶段一致。涉及 `venue-formatting`。

<a id="cf32"></a>
## CF32 · 发表后更正与正式决定

**输入：** 用户发现发表表格中的两项数值转置，想准备更正材料。

**本次产物：** “列出原数值、更正数值、原始数据出处、受影响图表和结论；草拟发给编辑的说明，交由作者确认后按期刊流程发送。”

**取舍：** 保留错误影响分析与沟通准备，将正式通知类型留给实际流程。

**检查结果：** 没有把草稿状态写成已发布更正。涉及 `postpublication-correction`。

<a id="cf33"></a>
## CF33 · 文献证据与投稿分区

**输入：** 用户拟投 Q1/Q2；同题的一篇较低分区论文具有严格的故障注入和复现实验。

**本次产物：** “按研究问题和方法质量将其纳入竞争方法比较；选刊阶段再对投稿候选应用用户指定的分区条件。将贡献与证据差距写入研究地图。”

**取舍：** 保留目标分区偏好，同时保留对问题有实质贡献的研究证据。

**检查结果：** 综述纳入与投稿筛选使用各自判据。涉及 `evidence-review`、`indexing-metrics`。

## 后续验证方法

新增或修改场景时保留原输入、实际产物、采用规则、检查项目和执行方式。将这些输入交给新的模型会话可做独立复测；模型实际运行记录应单独存档，不能用本文件代替。程序层变动先增加失败回归，再运行完整测试。
